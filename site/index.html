04 / Normal or lockdown One tool call

choose your mode

In normal mode, GitHub changes get a reminder to the agent. It checks the target and user intent, then repeats the call to proceed. Enable lockdown for blocking security judgments.

InThe agent calls a tool

01 Normal mode default

GitHub change, workflow run or push→Reminder to the agent. The call has not run.
Agent checks and repeats the same call→Usual permissions, then the tool runs
Other calls, including GitHub reads→Usual permissions, then the tool runs

02 Lockdown mode opt in

Enabled gate finds a clear risk→Denied, with the reason
Gate allows the call→Usual permissions, then the tool runs

03 Output screening both modes

Output contains instructions aimed at the model→Agent gets a "treat as data" note
● ● ●GitHub reminder, excerpt
[ohmyjev] Before changing GitHub or pushing commits, double-check the repository, branch, target and effect.
Be sure this is what the user intended. This call has not run.
If the action is already authorized and correct, repeat the same tool call to proceed.

The agent does the review

One reminder per distinct call in the session. If the action is already authorized and correct, the agent can retry without asking you solely because of this reminder. Turn it off with githubReminders: false.

Choose lockdown

Run /omj config lockdown on for this session. Save it in your host settings for future sessions. Enabled gates can block risky calls and unverified done claims. Jev errors fail open; the local write-path restriction still applies.

You need a TypeSafe or OpenRouter key. Lockdown is off by default. GitHub reminders and the speed features are on; browse is opt in. See every feature.
